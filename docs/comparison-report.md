# 贪吃蛇 AI 对照评测

评测日期：2026-09-27。共 **2140 局**、**58 个评测配置**。模型和原项目代码未修改，未重新训练。

## 核心结论

1. 本次没有复现公开原版 CNN 在原安全规则下通关；这不证明原版永远无法通关，也不评价视频真实性。
2. 你的最终 CNN 配现有规则优于它只使用即时合法检查时的表现，但原版 CNN 配同样规则也有相近提升。单凭平均分提高不能把功劳都归于额外训练。
3. 在评测器中去掉不可能满足的空间比例门槛，改用模拟一步后的头尾可达检查，旧权重无需重训便能实测满盘。该方案仍有大量循环或长期吃不到食物，不能称为稳定必胜。
4. 12 个阶段检查点的初筛，以及 3 个候选的独立复测，都没有在现有规则下通关；更早或更晚的保存点均不能自动视为更好。

## 安全规则的问题及诊断性替换

当前 _check_action_future_safety 将中间身体视作障碍，只开放头尾。因此蛇长为 L 时，可达格数最多为 146-L；可达格数/蛇长最多为 (146-L)/L。

800 分时 L=83，比例上限约 0.759，而代码要求至少 1.12。结合各分段阈值，当前 750～1330 分的未来安全动作会全部被拒绝，再回退为即时合法动作。更精确地说，1340 分时普通移动仍会被拒绝，但吃食后只剩 6 个空格，可能触发例外放行；之前对话中“750～1340 分全部退回”的说法在这个边界上过宽。评测记录按百位分段的检查数、回退数、实际改变动作数保存在 checks.json。

本次 tail_guard（追尾检查）仅作为诊断性对照：

- 400 分前沿用原即时合法检查。
- 400 分起，对每个合法动作模拟蛇身移动；吃食时不释放尾巴。
- 模拟后已经满盘，或者在把中间身体作为障碍时蛇头能到达蛇尾，则允许该动作。
- 所有候选都被拒绝时，回退到即时合法动作。
- 不使用固定汉密尔顿环，不预知下一颗食物，不改食物生成规则，不调整权重。

这只是一步模拟加静态连通检查，不等于验证整条未来路径可执行。它能避免很多自锁，但仍可能长期绕圈；下一步值得研究的是多步动态路径检查、循环检测与脱困，而不是直接继续大规模训练。

## 复现协议和边界

- 上游固定提交：a067bfc10df56a16ee601d47c5736a7fa41a1a64。
- Python 3.8.20、PyTorch 2.0.1 CPU、NumPy 1.24.4、Gym 0.21.0、Stable-Baselines3/sb3-contrib 1.8.0。原保存环境的 Python 为 3.8.16，故不承诺跨版本逐位相同。
- 每个评测配置重新将 torch/NumPy 种子设为 271828。概率采样以批量方式执行，批量大小与活跃局数会影响具体随机抽样序列；这里比较的是固定可复现评测协议，不是逐条运行原 test_cnn.py。
- 保留原游戏的三次初始化/reset 食物抽样行为。每局单独保存 Python random 状态，隔离批量环境之间的全局 RNG 干扰。
- 原版和本地 snake_game.py 的文件哈希完全相同；CNN 观察编码和即时合法性检查保持相同语义。共享评测器跳过不影响动作选择的奖励计算，并已将状态转移与完整 wrapper 对照核验。
- 四条展示回放又单独用完整环境逐步执行，检查每步动作许可、最终得分和终止状态；两条通关示例的 144 个蛇身坐标均唯一。
- 确定性策略遇到完全相同的蛇身顺序、方向和食物位置重复时，记为 exact_cycle。期间没有吃食，环境 RNG 未前进，在该策略下将持续循环。
- 概率采样不因状态重复立即结束。连续 2000 步未吃食或累计 20000 步结束评测，记为截止未通关，不当成已经撞死，也不声称继续跑绝无通关可能。
- 本次的通关比例受到上述步数预算约束。平均分是停止时分数，满分 1410；没有将奖励值当作分数。
- 没有获得视频对应的确切权重版本、食物序列或操作记录，因此不能判断视频那一局与当前公开最终模型是否一一对应。

## 训练记录的含义

TensorBoard 中 PPO_2 和 PPO_3 均记录到 200015872 步；最终平均奖励分别约 27.46、25.56。由于奖励设计可能变化，二者不能直接作为强弱结论。现有日志未记录可直接使用的逐局通关率。

本地 final 的元数据确认种子 114514、200015872 步、gamma=0.94。gamma=0.94 是原版已有参数，并非适配时新增。本次已经证实仅改动作检查就能通关，因此没有证据把 gamma 单独认定为原先失败的原因。

本地 MLP 的权重元数据为约 1 亿步，但 PPO_MLP 日志到约 2 亿步；日志与权重不能只凭目录名直接认定为同一次最终产物。较新的 400 个常规 CNN 检查点文件时间位于 6 月 8～9 日，另外 3 个早期文件来自 5 月 17 日；没有在现目录发现单独保存的 PPO_2 全套权重目录。
